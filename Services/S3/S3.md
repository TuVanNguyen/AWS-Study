# S3 (Simple Scalable Storage)

### Purpose
* secure, scalable object-based storage

### General features
* designed for 99.95-99.99% availability, depending on s3 tier
* designed for 11 9's durability for data storage (99.999999999%)
    * can expect to lose an object every 10,000 years
* lifecycle management: can automatically delete objects or move them to different storage tiers
* server-side encryption
* access control lists for AWS accounts and groups
* bucket policies: specify what actions are allowed or denied 


### Storage features
* unlimited storage
* object-based
    * objects stored in "buckets"
    * objects have a key-value store
        * name of object is the **key**
        * data itself is the **value**
    * each object has a version id
    * versioning allows for retireving old versions, or rolling back to previous versions (including deleted objects)
    * each object has metadata that you can configure e.g content-type, last modified date, tags
    * objects can be up to 5 TB in size
* universal namespace: all aws accounts share the s3 namespace
    * each s3 bucket name must be globally unique
    * buckets have their own urls e.g https://bucket-name.s3.us-east-1.amazonaws.com/key-name

## Storage Classes
* cost: S3 standard > S3 Intelligent Tiering > S3-IA > Glacier

| Storage Class | Availability | Retrieval Time | # availability zones | Minimum Storage | Use Case |
|---------------|--------------|----------------|----------------------|-----------------|----------|
| S3 Standard | 99.99% | immediate | >= 3 | None | most workloads with frequent access |
| S3 Infrequent Access | 99.9% | immediate | >= 3 | 30 days | long-term storage, backups, disaster recovery|
| S3 Intelligent Tiering | 99.9% | immediate | >= 3 | 30 days | unpredictable access patterns; automatically moves data between S3 standard and S3-IA |
| S3 One Zone-Infrequent Access | 99.5% | immediate | 1 | 30 days | infrequently accesed, non-critical data|
| S3 Glacier Instant Retrieval | 99.9% | milliseconds | >= 3 | 90 days | long-lived data accessed about once per quarter|
| S3 Glacier Flexible Retrieval | 99.99% | minutes or hours | >= 3 | 90 days | long-term archiving |
| S3 Glacier Deep Archive | 99.99% | default: 12 hrs | >=3 | 180 days | rarely accessed data archiving |

## Security

### Default
* all new buckets are private: only bucket owner can upload, read, delete, etc files

### Bucket Policies
* to setup access control for buckets
* can't apply to specific objects within bucket, needs to apply to entire bucket
* written in json

### Bucket Access Control Lists
* applied to objects within buckets
* define which accounts/groups can access objects

### S3 Access Logs
* log all requests made to buckets

## Encryption
* To protect data against unauthorized access

### Options
* Encryption in Transit (across network)
    * SSL//TLS
    * HTTPS: encrypts communication with website (e.g when entering password)
* Encryption at rest (e.g server-side encryption)
    * SSE-S3: S3 managed keys using AES 256-bit encryption (default)
    * SSE-KMS: AWS Key Management Service managed keys
    * SSE-C : customer provided keys
* Encryption at rest at Client Side
    * client (you) encrypt files yourself before uploading to s3

## CORS (Cross-Origin Resource Sharing)
* By deault through a web-browser, you can't access the objects of one s3 bucket linked in another s3 bucket
    * recall that s3 buckets have their own unique domain
* Workaround: include the domain of other bucket in the CORS section of bucket permissions
